# 중고책 교환 — 독자끼리 책 한 권씩을 동네 서점에 맡겨 무상으로 바꾼다

## 결정

- **무상 1:1 교환만 한다.** 책 한 권과 책 한 권을 바꾼다. 돈·포인트가 독자 사이에 오가지 않는다.
  독자 간 직접 결제는 전자금융업 등록이 필요하다(`context/constraints.md` 비싼 것). 포인트 차액 보정도 하지 않는다 — 등급 차이를 값으로 매기기 시작하면 사실상 거래가 된다.
- **서점이 맡김 장소다.** 두 사람이 만나지 않는다. 등록자가 등록할 때 고른 참여 서점에 둘 다 맡기고, 둘 다 맡겨지면 각자 상대 책을 받아 간다.
  서점은 **코드만** 본다(맡김 코드·픽업 코드, 4자리). 독자 실명·연락처를 서점에 넘기지 않는다는 제약(`constraints.md` 못 바꾸는 것)과 "픽업은 주문 번호로" 관행을 그대로 따른다.
- **동네는 구 단위로 고른다.** 실시간 위치를 수집하지 않는다(`constraints.md` 비싼 것 — 위치 기반 실시간 매칭). 등록할 때 구를 고르고, 맡길 서점은 그 구의 참여 서점 중에서 고른다. 둘러보기는 구 필터 하나다.
- **서로 보이는 신원은 닉네임뿐이다.**
  - 둘러보기 목록·상세에는 닉네임을 **보이지 않는다** — 책 제목·등급·사진·구·맡김 서점만. 한 사람의 등록 목록을 모아 볼 수 없게 하려는 것이다(열거 방지). 공개 근거: 등록자가 교환 상대를 찾으려고 스스로 올린 책 정보이고, 사람을 식별하는 값은 빠진다.
  - 요청이 오가는 순간부터 **당사자 둘에게만** 서로의 닉네임과 보낼 책이 보인다.
  - 요청자가 내민 책(사진 포함)은 그 요청을 받은 등록자에게만 보인다.
  - 서점(사장님·직원)은 코드와 책 제목·등급만 본다. 닉네임도 안 본다.
  - 채팅·자유 메시지는 두지 않는다. 연락처 교환 경로가 되고, 신고 대상이 늘어난다.
- **요청은 내 등록 책 중 하나를 골라 보낸다.** 등록하지 않은 책으로는 요청할 수 없다(교환 대상도 등급·사진 검증을 똑같이 거치게).
  한 책에 요청이 여러 건 올 수 있고, 등록자가 하나를 수락하면 나머지는 자동 거절된다.
- **기한과 노쇼.** 확정 뒤 3일 안에 맡기지 않거나, 보관 시작 뒤 7일 안에 받아 가지 않으면 노쇼 1회. 90일 안에 2회면 30일 동안 교환 요청·수락을 막는다(둘러보기·등록은 된다).
  확정 뒤 본인이 취소해도 노쇼 1회다 — 상대가 이미 서점에 다녀왔을 수 있다.
- **만료되면 이미 맡긴 책은 주인에게 돌아간다.** 맡긴 쪽은 반환 코드로 7일 안에 되찾아 간다. 그 뒤 미회수 책의 처리는 남은 질문(사업 결정).
- **상태 등급 분쟁은 공통 신고로 받는다.** 등급은 A/B/C 세 단계이고 설명 문구를 등록 화면에 고정해 보여 준다.
  받은 뒤 24시간 안에 "상태 등급이 설명과 달라요" 사유로 신고하면 운영자가 등록 사진과 신고 사진을 비교해 판단한다.
  결과는 **경고 또는 노쇼 1회 부과**이고, 책을 되돌리는 원상 복구는 하지 않는다(다시 서점을 오가게 만드는 비용이 더 크다).
- **서점은 재고에 넣지 않는다.** 교환 책은 서점 재고·주문·정산과 무관하다. 재고에 넣으면 판매 상품처럼 보이고 정산 키(ISBN)가 섞인다.
- **ISBN 없는 책은 이번에 받지 않는다.** 서점 임시 코드는 재고용이고 독자가 받을 수 없다. 검색 실패 화면에 그렇게 안내한다.
- **하지 않기로 한 것**: 포인트 보정, 택배 교환, 직거래, 채팅, 실시간 위치 매칭, 여러 권 묶음 교환, 서점 파트너 앱 화면(이번 범위 밖 — 코드 확인 화면은 별도 명세).

- 서점의 코드 확인 API는 "그 서점에 걸린 진행 중인 건" 안에서만 코드를 맞춰 본다. 코드를 넣어 다른 서점의 건을 찾을 수 없다. 코드 오입력은 서점별로 횟수 제한을 둔다(값은 남은 질문).

## 상태 변화

| 지금 | 계기 | 다음 | 되돌리기 |
|---|---|---|---|
| (없음) | 등록자가 등록 | 등록됨 | 등록자가 내리기 → 사라짐 |
| 등록됨 | 다른 독자가 내 등록 책으로 요청 | 요청 받음 | 요청자가 요청 취소, 요청 전부 거절·만료 → 등록됨 |
| 요청 받음 | 등록자가 수락 | 교환 확정(맡기기 대기) | 불가. 이후 취소는 노쇼 1회 |
| 요청 받음 | 등록자가 거절 / 3일 무응답 | 등록됨(그 요청만 거절·만료) | — |
| 교환 확정 | 서점이 두 맡김 코드를 모두 확인 | 서점 보관 중 | 불가 |
| 교환 확정 | 3일 안에 한쪽이라도 안 맡김 | 만료·취소(안 맡긴 쪽 노쇼 1회) | 불가. 맡긴 쪽은 반환 코드로 7일 안에 회수 |
| 교환 확정 | 한쪽이 취소 | 만료·취소(취소한 쪽 노쇼 1회) | 불가 |
| 교환 확정·보관 중 | 운영자 강제 취소(사유 필수) | 만료·취소(노쇼 아님) | 불가 |
| 서점 보관 중 | 서점이 두 픽업 코드를 모두 확인 | 완료 | 불가. 등급 분쟁은 신고로 |
| 서점 보관 중 | 7일 안에 한쪽이 안 받아 감 | 만료·취소(미픽업, 안 받은 쪽 노쇼 1회) | 받아 간 쪽의 교환은 그대로 유효 |
| 완료 | 받은 뒤 24시간 안에 등급 신고 | 완료(신고 처리 중) | 원상 복구 없음. 경고 또는 노쇼 부과 |

예외 흐름:

- **동시 요청** — 같은 책에 요청이 여러 건 와도 수락은 하나만 성공한다. 수락 순간 나머지는 자동 거절되고 요청자에게 알림이 간다.
- **같은 책을 두 요청에 내밀기** — 요청자의 책 하나가 여러 요청에 걸려 있다가 하나가 확정되면, 나머지 요청은 자동 취소된다.
  요청자가 동시에 보낼 수 있는 요청은 3건으로 묶는다.
- **노쇼 제한 중** — 요청·수락 버튼 자리에 "○월 ○일까지 교환 제한 · 이유: 기한 넘김 2회"를 보여 준다(조용히 비활성화하지 않는다). 다음 행동은 "제한 이유 보기"·"문의하기".
- **ISBN 검색 실패** — "불러오지 못함"(검색 서비스 오류: 다시 시도)과 "찾지 못함"(번호 확인, ISBN 없는 책 불가 안내)을 다르게 그린다.
- **서점 참여 해지** — 진행 중인 건이 있는 서점은 해지가 그 건들이 끝날 때까지 미뤄진다. 등록됨 상태의 책은 맡김 서점을 다시 고르라는 알림을 받는다.
- **서점 휴무** — 맡김·보관 기한은 달력일로 센다. 휴무일 보정은 하지 않고, 등록·확정 화면에 서점 영업시간 링크를 둔다.
- **분실·파손(서점 보관 중)** — 신고로 접수하고 운영자가 처리한다. 서점 책임 범위는 남은 질문.

## 숫자

| 값 | 얼마 | 운영이 배포 없이 바꾸나 |
|---|---|---|
| 요청 응답 기한 | 3일 | 예 (→ 어드민 화면 필요) |
| 맡기기 기한(확정 뒤) | 3일 | 예 (→ 어드민 화면 필요) |
| 픽업 기한(보관 시작 뒤) | 7일 | 예 (→ 어드민 화면 필요) |
| 만료 시 반환 회수 기한 | 7일 | 예 (→ 어드민 화면 필요) |
| 등급 이의 기한(받은 뒤) | 24시간 | 예 (→ 어드민 화면 필요) |
| 노쇼 제한 기준 | 90일 안에 2회 | 예 (→ 어드민 화면 필요) |
| 노쇼 제한 기간 | 30일 | 예 (→ 어드민 화면 필요) |
| 동시 등록 권수 | 10권 | 예 (→ 어드민 화면 필요) |
| 동시 보내는 요청 | 3건 | 예 (→ 어드민 화면 필요) |
| 사진 장수 | 1~3장 | 아니오 |
| 코드 길이 | 4자리(영문 대문자·숫자) | 아니오 |
| 상태 등급 | A/B/C 3단계 | 아니오 (등급 문구 변경은 기획 승인) |

- 운영이 바꾸는 값은 어드민 › 교환 설정 화면이 같이 필요하고, 바꿀 때 이전 값→이후 값·사유가 감사 기록에 남는다.
- 값을 바꿔도 **이미 진행 중인 건의 기한은 그 건이 시작될 때의 값**을 쓴다.

## 기존 코드와의 관계

| 구분 | 무엇 | 근거 |
|---|---|---|
| 재사용 | 신고 — 등급 분쟁·불쾌한 내용·다른 책 도착을 공통 신고 사유로 추가한다. 교환 전용 신고 화면을 만들지 않는다 | `context/features.md` 신고 · `context/constraints.md` 재사용할 것 |
| 재사용 | 알림 — 종류만 추가한다: 요청 받음·수락·거절·맡김 기한 임박·보관 시작·픽업 기한 임박·만료·운영자 취소. 묶음 규칙(같은 종류 10분 1건)을 그대로 쓴다 | `features.md` 알림 · `constraints.md` 알림 묶음 |
| 재사용 | 어드민 감사 기록 — 운영자 강제 취소·건 상세 열람·설정 변경 | `constraints.md` 재사용할 것 |
| 재사용 | 서점 페이지 — 참여 서점에 "교환 맡김 가능" 표시와 영업시간 링크 | `features.md` 서점 페이지 |
| 재사용 | ISBN 서지 조회 — 책 식별은 ISBN | `constraints.md` 못 바꾸는 것(ISBN 식별) |
| 재사용 안 함 | 재고 — 교환 책은 서점 재고·주문·정산에 넣지 않는다 | `features.md` 재고·정산 — 판매 상품과 섞이면 정산 키가 오염된다 |
| 재사용 안 함 | 포인트 — 교환에 포인트를 쓰지 않는다 | `constraints.md` 비싼 것(결제 적립 포인트 환불) — 보정이 거래가 된다 |
| 신규 | 교환 등록·요청·교환 건 상태 머신, 맡김·픽업·반환 코드 | 비슷한 기능이 없다. 주문 픽업은 결제가 전제라 재사용할 수 없다 |
| 신규 | 노쇼 카운터와 교환 제한 | 지금 없는 데이터다. 교환 기능 안에만 둔다 |
| 신규 | 서점 "교환 참여" 여부와 코드 확인 API (파트너 화면은 별도 명세) | 서점이 맡김 장소가 되려면 필요 |
| 신규 | 어드민 › 교환 설정·교환 건 화면 | 운영이 바꾸는 숫자가 있다(`context/rules.md` 운영) |
