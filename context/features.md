# 이미 있는 기능

> 🧪 예시 — 가상의 동네 책방 플랫폼 "책숲". 현황 버전 `a1b2c3d` (2026-10-07). [README](README.md)

프로토타입을 그리기 전에 여기서 "이미 있나"를 먼저 찾는다. 있으면 재사용하고, 명세의 「기존 코드와의 관계」에 적는다.

## 앱

| 앱 | 브랜드 코드 | 누가 쓰나 |
|---|---|---|
| 책숲 | `reader` | 독자 — 책방을 찾고, 모임에 가고, 책을 산다 |
| 책숲 파트너 | `partner` | 서점 사장님·직원 — 재고·모임·정산을 관리한다 |

## 역할

| 역할 | 코드 이름 | 어떻게 정해지나 |
|---|---|---|
| 비로그인 | `guest` | 세션 없음 |
| 독자 | `reader` | 로그인 |
| 단골 | `regular` | 그 서점을 "단골 등록"한 독자. **서점마다 따로** 정해진다 |
| 사장님 | `owner` | 서점 주인. 서점당 1명 |
| 직원 | `staff` | 사장님이 초대. 서점당 최대 5명. 정산은 못 본다 |
| 운영자 | `admin` | 책숲 운영. 모든 조작에 감사 기록 |

## 기능

| 기능 | 무엇 | 권한 요지 | 재사용 포인트 |
|---|---|---|---|
| 서점 페이지 | 서점 소개·영업시간·공지 | 읽기 누구나, 쓰기 사장님·직원 | 서점 페이지에 탭을 붙일 수 있다(최대 6개) |
| 단골 등록 | 서점 즐겨찾기. 등록 일수(`regularDays`)를 센다 | 독자 | **등록 일수는 이미 있다** — 새로 세지 않는다 |
| 포인트 | 적립·사용 원장. 결제 적립분과 이벤트 지급분을 나눠 기록 | 본인만 잔액 조회 | 차감·환불 API가 있다. **결제 적립분 환불은 결제 취소 규정**을 따른다 |
| 재고 | 서점별 책 재고(ISBN 단위) | 쓰기 사장님·직원 | 재고 변경 이벤트가 있다 — 입고 알림이 여기 붙을 수 있다 |
| 주문·결제 | 책 주문, 매장 픽업 | 독자 | 결제·취소·부분 환불이 있다 |
| 정산 | 월 1회 판매 정산 | 사장님만 | 정산 내역 조회만 있다. 보류·이의 제기는 없다 |
| 신고 | 모든 콘텐츠 공통 신고 접수·처리 | 접수 독자, 처리 운영자 | **신고는 이걸로 통일**한다. 기능마다 따로 만들지 않는다 |
| 알림 | 앱 푸시·알림함 | 본인 | 묶음 규칙이 있다(같은 종류 10분 1건) |

## 운영이 배포 없이 바꾸는 값 (지금 있는 것)

| 값 | 어디서 바꾸나 |
|---|---|
| 판매 수수료율 | 어드민 › 정산 설정 |
| 포인트 적립률 | 어드민 › 포인트 설정 |
| 알림 묶음 간격 | 어드민 › 알림 설정 |

새 기능의 숫자를 "운영이 바꾼다"로 정하면, 어드민 화면이 같이 필요하다는 뜻이다. 명세에 그렇게 적는다.
