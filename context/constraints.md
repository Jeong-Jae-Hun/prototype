# 제약 — 비싼 것, 못 바꾸는 것, 재사용할 것

> 🧪 예시 — 가상의 동네 책방 플랫폼 "책숲". 현황 버전 `a1b2c3d` (2026-10-07). 개발 담당이 쓴다. [README](README.md)

프로토타입은 이 제약을 몰라도 그릴 수 있다. 그래서 여기 적는다. 명세가 아래와 부딪치면 「기존 코드와의 관계」에 **충돌**로 적고,
리뷰에서 개발 담당이 판단한다.

## 못 바꾸는 것

| 제약 | 왜 |
|---|---|
| 책은 ISBN 으로 식별한다. ISBN 없는 책(독립출판 일부)은 서점이 임시 코드를 받는다 | 재고·주문·정산이 모두 ISBN 키다 |
| 금액 단위는 원 정수, 포인트도 정수 | 원장·정산이 정수 컬럼이다 |
| 정산 주기는 월 1회, 매월 10일 지급 | 서점 계약서에 들어 있다 |
| 독자 실명·연락처를 서점에 넘기지 않는다 | 픽업은 주문 번호로 한다. 개인정보 처리 위탁 범위 밖이다 |

## 비싼 것

| 무엇 | 왜 비싼가 | 대안 |
|---|---|---|
| 실시간 재고 (초 단위) | 서점 POS 연동이 하루 2회 동기화다 | "오늘 오전 기준" 표시 |
| 독자 간 직접 결제 | 전자금융업 등록이 필요하다 | 교환은 무상 교환만, 또는 포인트로 |
| 위치 기반 실시간 매칭 | 위치 수집 동의·보관 규정이 붙는다 | 동네(구 단위) 선택 |
| 결제 적립 포인트 환불 | 결제 취소 규정·기간이 붙는다 | 이벤트 지급 포인트만 보상에 쓴다 |

## 재사용할 것

- **신고** — 공통 신고 기능을 쓴다. 기능마다 신고 화면을 새로 만들지 않는다.
- **단골 등록 일수** — 이미 센다. "단골 n일 이상" 조건은 새 데이터 없이 된다.
- **재고 변경 이벤트** — 입고·품절을 따로 감지하지 않는다. 이 이벤트를 구독한다.
- **알림 묶음** — 같은 종류 10분 1건 규칙이 이미 있다. 새 기능은 종류만 추가한다.
- **어드민 감사 기록** — 운영자 조작은 공통 감사 로그로 남는다.
