# 제약 — 비싼 것, 못 바꾸는 것, 재사용할 것

> 🧪 예시 — 가상의 제품 "팬온". 현황 버전 `a1b2c3d` (2026-10-07). 개발 담당이 쓴다. [README](README.md)

프로토타입은 이 제약을 몰라도 그릴 수 있다. 그래서 여기 적는다. 명세가 아래와 부딪치면 「기존 코드와의 관계」에 **충돌**로 적고,
리뷰에서 개발 담당이 판단한다.

## 못 바꾸는 것

| 제약 | 왜 |
|---|---|
| 로그인은 외부 계정 연동 하나뿐이다 | 계정 체계 전체가 그 위에 있다 |
| 금액 단위는 포인트 정수다. 소수점 없음 | 원장이 정수 컬럼이고 결제 정산이 거기 맞춰져 있다 |
| 한 주의 경계는 한국 시간 월요일 00:00 | 통계·정산이 이 기준이다. 기능마다 다르게 두면 숫자가 안 맞는다 |
| 사용자 식별자를 화면·URL에 노출하지 않는다 | 공개 프로필 외에는 내부 id가 나가면 안 된다는 보안 기준 |

## 비싼 것

| 무엇 | 왜 비싼가 | 대안 |
|---|---|---|
| 실시간 순위 (초 단위 갱신) | 소켓 채널을 새로 열어야 하고 부하가 크다 | 1분 주기 갱신이면 기존 캐시로 된다 |
| 팬 수만큼 메시지 복제 저장 | 채널당 멤버 수만 명 → 쓰기 폭증 | 원문 한 줄 저장 + 읽을 때 개인화 |
| 동영상 업로드·인코딩 | 인코딩 파이프라인이 클립 전용이다 | 클립을 재사용하거나 이미지로 |
| 충전 포인트 환불 | 결제 취소 규정·기간이 붙는다 | 무료 포인트만 받거나, 환불을 포인트 반환으로 한정 |

## 재사용할 것

- **신고** — 공통 신고 기능을 쓴다. 기능마다 신고 화면을 새로 만들지 않는다.
- **멤버십 가입 일수** — 이미 센다. "가입 n일 이상" 조건은 새 데이터 없이 된다.
- **알림 묶음** — 같은 종류 10분 1건 규칙이 이미 있다. 새 기능은 종류만 추가한다.
- **어드민 감사 기록** — 운영자 조작은 공통 감사 로그로 남는다. 새 어드민 화면도 거기에 붙인다.
