# 공용 규칙 — 모든 레포를 아우르는 규칙의 사본

> 🧪 예시 — 가상의 "책숲" 조직. 정본: 조직 공용 규칙 레포 `example/org-rules`(가상) · 버전 `r42`. [README](README.md)

이 파일은 **사본이다.** 고치려면 정본 레포에 PR 을 올린다. 정본이 바뀌면 각 레포(제품·프로토타입·어드민…)로
"규칙 갱신" PR 이 자동으로 열린다 — `context/` 의 다른 파일과 같은 길이다.

## 규칙은 세 층이다

```
조직 공용 (이 파일)          모든 레포 — 개인정보·보안·접근성·문구 원칙
  └ 레포 (AGENTS.md)         그 레포만의 방식 — 이 레포라면 "명세가 정본", 폴더 규칙
      └ 폴더 (SPEC.md 등)    그 기능만의 결정
```

- 충돌하면 **좁은 쪽이 이긴다**(폴더 > 레포 > 조직). 그래야 기능마다 맞는 결정을 내릴 수 있다.
- **단, 아래 「항상」 표시는 예외다.** 좁은 쪽이 덮을 수 없다. 덮으려면 이 파일을 고친다.

## 개인정보 — 항상

- 다른 사람의 데이터는 **비공개가 기본값**이다. 공개하려면 명세에 공개 근거를 적는다.
- 화면에서 숨기는 것은 권한이 아니다. 서버가 막는다고 명세에 적는다.
- 사용자 식별자(내부 id·실명·연락처)를 화면·주소에 내보내지 않는다.
- 목록·검색·내보내기도 같은 기준이다. 하나씩은 막고 목록으로는 다 보이는 실수가 제일 흔하다.

## 운영 — 항상

- 운영자가 바꾸는 값이 있으면 **어드민 화면이 같이 필요하다.** 코드 상수로 두지 않는다.
- 운영자의 조작과 민감한 조회는 **감사 기록**을 남긴다 — 누가·언제·무엇을·이전 값→이후 값·사유.

## 화면

- **조용히 실패하지 않는다.** 안 되면 왜 안 되는지와 다음 행동을 보여 준다.
- **막다른 길을 만들지 않는다.** 빈 상태·권한 없음 화면에도 다음 행동 버튼을 둔다.
- **돈이 나가기 직전에 알린다.** 차감 금액·남는 금액·환불 조건을 확정 버튼 앞에 보여 준다.
- 실패와 빈 상태를 같은 모양으로 그리지 않는다. "불러오지 못함"과 "없음"은 다르다.
- 주요 버튼은 높이 44px 이상. 색만으로 상태를 구분하지 않는다(글자·아이콘을 같이).
