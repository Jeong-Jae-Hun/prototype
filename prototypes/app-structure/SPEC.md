# 앱 구조 — 독자 앱과 파트너 앱의 탭 기준선

| 항목 | 내용 |
|---|---|
| 종류 | 구조 |
| 상태 | 초안 |
| 브랜드 | reader / partner |
| 담당 | 기획 @기획-예시 · 디자인 @디자인-예시 · 개발 @개발-예시 · **영향 받는 기능 담당 전원** (book-club · book-swap · reading-challenge · restock-alert · settlement) |
| 현황 버전 | a1b2c3d |

> 구조 프로토타입의 화면은 `app-structure/shell.js`(앱 셸)과 사이트맵이다.
> 셸을 바꾸면 **모든 기능 프로토타입의 미리보기가 새 구조로 다시 그려진다** — PR 의 화면 비교에서 확인한다.

## 결정

이 문서는 **바꾸는 제안이 아니라 기준선**이다. 지금 `shell.js` 의 `APPS` 가 정한 구조를 명세로 옮겨, 이후 구조 개편 PR 이 "무엇에서 무엇으로" 바뀌는지 대조할 바탕을 만든다.

| 결정 | 왜 |
|---|---|
| **앱을 둘로 나눈다** — 책숲(`reader`)과 책숲 파트너(`partner`). 한 앱에서 "사장님 모드"로 전환하지 않는다 | 쓰는 사람·하는 일이 다르다(둘러보기·신청 vs 재고·정산). 한 앱에 모드를 두면 탭이 모드마다 바뀌어 길을 잃고, 독자 화면에 정산 같은 민감 메뉴의 흔적이 남는다. 권한 경계도 앱 경계와 같아져 서버 검사가 단순해진다 |
| **탭은 앱마다 최대 5개** | 모바일 하단 탭 바(360px)에서 글자가 잘리지 않는 상한. 지금 독자 5개 · 파트너 4개. 6번째가 필요하면 기존 탭 안으로 넣거나 이 구조 프로토타입부터 바꾼다 |
| **정산 탭은 사장님만** — 직원에게는 잠그지 않고 **숨긴다** | `context/features.md`: 정산은 사장님만, 직원은 정산을 못 본다. 볼 수 없는 메뉴로 탭 자리를 쓰지 않는다. 화면에서 숨기는 것과 별개로 **서버가 정산 조회를 막는다**(`context/rules.md` — 숨김은 권한이 아니다) |
| 같은 기능은 두 앱에서 **같은 slug** 를 쓰고 브랜드로 화면을 가른다(`book-club`, `restock-alert`) | 명세 한 벌로 양쪽 규칙을 맞춘다. 독자 쪽은 신청·구독, 파트너 쪽은 개설·입고 처리 |
| 메뉴 정본은 `shell.js` 의 `APPS` 하나. 사이트맵은 그걸 읽어 그린다 | 구조를 두 벌로 적으면 한쪽만 고치는 날이 온다 |

하지 않기로 한 것:

- 한 앱 안의 독자/사장님 모드 전환 — 위 이유.
- 권한 없는 탭을 잠금 아이콘으로 보여 주기(직원의 정산) — 숨긴다. 단 **비로그인의 로그인 필요 탭은 보여 주고 잠근다**(로그인하면 쓸 수 있으므로 기능을 알리는 편이 낫다).
- 운영자 전용 탭 — 운영자는 앱이 아니라 어드민에서 본다.

## 화면 지도

| 앱 | 지금 | 바꾼 뒤 |
|---|---|---|
| 책숲 (`reader`) | 홈 · 모임(`book-club`) · 교환(`book-swap`) · 챌린지(`reading-challenge`) · 내 서재(`restock-alert`) — 5/5 | 현재와 같음 — 기준선 |
| 책숲 파트너 (`partner`) | 대시보드 · 모임 운영(`book-club`) · 입고(`restock-alert`) · 정산(`settlement`, 사장님만) — 4/5 | 현재와 같음 — 기준선 |

두 앱 공통 화면: `book-club`, `restock-alert` (사이트맵이 `APPS` 에서 계산해 "두 앱 공통" 태그를 단다).

## 이동 규칙

| 상황 | 동작 |
|---|---|
| 탭 순서 | `APPS.nav` 배열 순서 = 탭 순서. 탭을 누르면 그 탭 `slugs` 의 첫 화면으로 간다 |
| 뒤로 가기 | 탭 안의 이전 화면으로. 탭 첫 화면에서는 앱을 나간다(다른 탭으로 돌아가지 않는다) |
| 비로그인이 로그인 필요 탭을 누름 | 화면을 바꾸지 않고 **로그인 시트**를 띄운다 → 로그인을 마치면 **누른 탭으로 돌아간다**. 시트를 닫으면 원래 화면에 그대로 |
| 책숲에서 로그인 없이 되는 탭 | 홈 · 모임(둘러보기). 교환 · 챌린지 · 내 서재는 로그인 필요 |
| 책숲 파트너 비로그인 | 모든 탭이 로그인 필요. 로그인 후 사장님·직원 계정이 아니면 "서점 등록 신청" 안내로 보낸다(막다른 길 금지) |
| 직원 | 정산 탭이 **없다**(숨김). 정산 주소로 직접 들어오면 "사장님만 볼 수 있어요" + 대시보드로 가기 |
| 운영자 | 앱에는 운영자 탭이 없다. 어드민에서 대리 조회하며 조회마다 감사 기록(누가·언제·무엇을·사유) |
| 딥링크(푸시·공유 링크) | 해당 화면으로 바로 연다. 로그인이 필요하면 위 로그인 시트 → 그 화면으로 복귀. 파트너 푸시가 독자 앱으로 열리는 경우는 남은 질문 |

## 영향 받는 화면

기준선이라 바뀌는 화면은 없다. 이 구조를 기준으로 각 기능이 자기 탭에 맞는지만 확인받는다.

| 화면(slug) | 무엇이 바뀌나 | 담당 확인 |
|---|---|---|
| book-club | 바뀌지 않음. 책숲 「모임」 · 파트너 「모임 운영」 두 탭에 걸린다 | @모임-담당 ☐ |
| book-swap | 바뀌지 않음. 책숲 「교환」, 로그인 필요 | @교환-담당 ☐ |
| reading-challenge | 바뀌지 않음. 책숲 「챌린지」, 로그인 필요 | @챌린지-담당 ☐ |
| restock-alert | 바뀌지 않음. 책숲 「내 서재」 · 파트너 「입고」 두 탭에 걸린다 | @입고알림-담당 ☐ |
| settlement | 바뀌지 않음. 파트너 「정산」, 사장님만(직원에게 숨김) | @정산-담당 ☐ |

## 옛 주소 → 새 주소

없음. 이 문서는 지금 구조를 기록하는 기준선이라 주소가 바뀌지 않는다. 다음 구조 개편 PR 이 탭·slug 를 옮기면 그때 이 표에 옛 주소를 채운다.

| 옛 주소 | 새 주소 | 처리 |
|---|---|---|
| (없음 — 기준선) | (없음) | 해당 없음 |
